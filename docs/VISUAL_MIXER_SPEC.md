# SML Visual Mixer — revision 1.6


Status: PLANNED. Owner requests a close functional counterpart to iZotope Visual Mixer integrated with the actual DAW mixer. This specification defines original SML presentation and native control behavior; it does not establish pixel-exact or full product parity. No implementation or usability measurement executed.

## Evidence and reference scope
Primary source: iZotope Neutron 4.0.2 Visual Mixer documentation, accessed 2026-10-11:
https://s3.amazonaws.com/izotopedownloads/docs/neutron4/en/visual-mixer/index.html
The documented controller uses compatible plugin instances, horizontal pan, vertical output gain, node-side width handles, a visibility/name list, three snapshots, and activity/clipping indicators. Mono-instance pan/width are restricted in that documented version. Our native DAW view intentionally allows mono-track pan; width remains unavailable for a truly mono signal. Reference is this documented version, not an uninspected latest release. No source/assets copied. Assistant functionality is outside this spatial-control scope.

All mappings, architecture, ranges, test tolerances and additional operations below are original product decisions, not iZotope implementation claims. The request for two mixers means two synchronized control surfaces over one audio mixer; no duplicate summing engine or extra gain stage for merely opening the view.

## VM01 — entry points and views
Provide Console / Visual / Split controls in the mixer workspace. Console retains professional channel strips; Visual displays the soundstage canvas; Split shows both simultaneously. Use existing docking/window infrastructure if available. Closing or hiding either view cannot change sound. Persist chosen view, canvas zoom and filters per session. Default first launch remains the familiar recording/console view.

One node per visible native audio track, bus and FX return, keyed by immutable channel ID. Master is a fixed separate strip, not a pannable soundstage node. Show track name/color, selected state, route/bus badge, mute/solo state, activity and clipping. A searchable channel list supports selection, rename, hide/show, track/bus/return filters and reveal-hidden selection. Hiding only affects the view; it never mutes. Node overlap uses label callouts, cycling or the list for selection; never move audio parameters just to separate overlapping graphics. No decorative forced-layout physics. Provide keyboard focus, accessible names/value readouts, numeric editing and reset actions.

## VM02 — direct manipulation and shared values
Horizontal node center controls the existing channel pan/balance position; vertical center controls that channel's existing fader gain, NOT an additional trim or plugin gain. Readouts include exact dB and pan value. Use normalized x in [-1,1] and existing canonical fader conversion. Start with visible vertical range -60..+12 dB, adapting to narrower actual engine limits rather than expanding them accidentally. Values outside visible bounds get edge indicators and exact numeric access; opening the view cannot clamp existing values. True -infinity is a distinct bottom detent using the existing fader's zero gain, not the mute flag. Add 0 dB and center guides, modifier-constrained axis drag, fine adjustment, double-click numeric edit and explicit reset. Map conventional pan endpoints consistently in both views.

Horizontal dragging follows the current M02 panner type. In stereo Pan, the old rigid-span rule would lock full-width nodes. Use an explicit center/span mapping: derive c=(pL+pR)/2 and h=abs(pR-pL)/2 with channel order sign retained. During one horizontal gesture retain its starting h; requested c is the node position, effective h=min(h,1-abs(c)); endpoints are c±effective_h with original channel order. Display the resulting span and “span narrowed at edge” feedback. Undo restores original endpoints; crossing back within that gesture restores its starting span. Console endpoint edits remain authoritative; the next gesture derives a new c/h. This is original SML behavior, not documented iZotope equivalence. In Balance, use the balance parameter. Display the type; never silently change modes to perform a gesture. Existing automation stays bound to the same parameter IDs. This view's width handles control VM03 Stereo Width; they must not also change M02 stereo-panner spread.

One pointer gesture is one undo transaction; Escape cancels the gesture. Multi-selection preserves relative finite-dB/center offsets and uses a common allowed delta at range limits. Locked member rejects the whole gesture, avoiding partial edits. A -infinity fader has no finite dB offset: reject group vertical drag containing it with a numeric/set-level action, while horizontal movement remains available. Stereo span adjusts as just defined, with visible feedback. Width handles act on the selected node initially; do not introduce ambiguous group width gestures. Numeric edits and resets obey the same locks, automation arbitration and undo rules.

## VM03 — native width shared by both mixers
Audit existing channel width first; reuse only if its semantics are documented and consistent. Add a native Stereo Width control to Console as well as Visual. For a stereo signal, initial original algorithm is M=(L+R)/2, S=(L-R)/2, Lout=M+w*S, Rout=M-w*S, w in [0,2], default 1 (100%). At 0%, dual-mono; 100% is identity; 200% doubles side amplitude. At settled w=1, explicitly copy/pass through L/R without M/S arithmetic to preserve exact samples (float sum/difference can otherwise lose low-level channel data). During transitions use the documented 10 ms smoothing and test the final unity state after settling. Side handles map to this one parameter and show numeric %. This is NOT a claimed reconstruction of iZotope's DSP. Increased width can increase peaks; do not add hidden auto-gain or limiter.

Place width after user Pre inserts and before fader and pre-fader send tap; user Post inserts remain downstream, per SL02. Confirm actual graph and record any necessary rework. Pre-fader sends are therefore post-width in the new feature; preserve legacy sessions with width=100%. Bus/Tape/Pre/Post insert order is now authoritative in MIXER_SLOT_SPEC.md SL02; width stays before the pre-fader send tap and fader/panner. No duplicate width processing in the UI. Disable width for mono at the actual processing point; stereo output from an insert can enable it when channel format supports that. No fabricated mono stereo enhancement. Smooth live width over 10 ms in the engine and use the identical path for playback/export. Distinguish native Stereo Width from M02 stereo-panner spread; document both and never collapse two independent controls into one value.

## VM04 — one authoritative model and real-time synchronization
Both views dispatch the same engine commands to the same channel/parameter IDs. A single model owns gain, pan, width, mute, solo and selection. Views subscribe to acknowledged revisions, with origin/gesture IDs to prevent feedback loops and stale writeback. Audio meters are read-only telemetry. Do not poll widget values to synchronize views or perform UI work on the callback. Use bounded/coalesced parameter transport with guaranteed final gesture value and discrete command delivery; no unbounded drag queue. Closing either view releases observers and leaves audio state intact.

Show the current applied/automated values in both views. Reuse the existing automation engine; Read mode follows automation, Touch/Latch/Write record native parameters only where those modes actually exist. In Read, automated parameters are read-only during playback unless the existing engine defines a temporary override; expose that behavior consistently. Do not invent an independent automation system for Visual. Snapshot recall occurs stopped in this pass because it may change panner type/format-affecting settings. Saving a snapshot during playback captures one coherent acknowledged model revision, not mixed UI values. On resumed Read automation, envelopes take precedence over recalled static values; explain that in the snapshot scope. Concurrent edits serialize by acknowledged engine order; deletion cancels active gestures safely. Out-of-order acknowledgments cannot overwrite a newer revision.

Real-time target: applied parameter visible in the other open view within 50 ms p95 under the existing 16-track workload, timestamped command-to-render. Audio command applied by the next processing block after engine dequeue, followed by documented smoothing. No hard zero-latency claim; report UI, block and smoothing latency separately. Meter presentation 30 Hz or better when visible, bounded CPU and no audio-thread locks/allocation. Retain existing xrun/callback/frame gates with Split open.

## VM05 — snapshots, routing and integrated summing
Provide three named A/B/C mix snapshots with explicit Save/Recall. Capture stable channel IDs, gain, panner type and coordinates, stereo width, mute/solo, and view visibility. Snapshot scope is shown beside controls. Exclude plugin states, routing, console model/drive/trim and automation envelopes; label them excluded rather than implying a whole-session snapshot. Recall is an atomic undoable batch for surviving IDs; report missing/deleted channels, leave newly created channels unchanged. Never recreate or reroute tracks. Apply standard smoothing. Snapshot capture/recall and all values survive save/reopen.

Visual selection can invoke existing Create Bus from Selection and Create FX Return commands; do not duplicate routing code. Selecting a bus shows its sources and optional noninteractive routing lines. Collapsing sources is visual only. Clearly distinguish changing a bus fader from changing its child faders to avoid accidental double adjustment. Show Summing/Tape slot state badges and use the shared slot inspector for edits; no separate Visual-only summing state. Logic-style pan laws apply identically in both views. External plugins require no bridge/Relay instance. No AI mix assistant, new spectral analyzer or extra DSP catalogue is added by this requirement.

## VM-T acceptance and evidence
Commands are established in Sprint 1 after inspecting the actual test/UI harness. Use these stimuli in headless engine tests plus available native interaction tests; source review alone cannot pass UI gates.
- VM-T1 Shared-state: change every gain/pan/width/mute/solo control in Console, Visual and engine command paths. Assert one model revision, correct acknowledged value and both views updated. Exercise deletion, rename, new channels and hidden channels. No echo-loop commands or stale rollback.
- VM-T2 Audio invariance: same deterministic project with Visual closed/open/Split must render identical samples. Dragging volume must apply gain exactly once. With Summing Clean, Tape None, unity slot trims and external plugins bypassed, test -6 dB gain within 0.01 dB and pan against M-T2. Loaded slot providers use the identical processing graph in both views; use declared deterministic fixtures until native models are approved.
- VM-T3 Width: impulses, identical L/R, L-only and opposite-polarity stereo at w=0,1,2; compare formula within 1e-6 peak error for normalized inputs. At w=1 output identity; mono average (Lout+Rout)/2 remains M within stated floating tolerance; w=0 removes side. Verify correct pre/post-send taps, stereo insert format changes, width handles do not change panner spread; center dragging narrows spread only according to VM02, and headroom above 0 dBFS without intermediate hard clipping.
- VM-T4 Gesture/undo: node drag + 100 intermediate updates creates one undo entry; undo/redo restores all selected IDs exactly. Escape restores initial values. Bounds, -infinity, locks, overlapping nodes, fine control and numeric edit behave as specified. Latest final drag event is never lost.
- VM-T5 Persistence/snapshots: A/B/C round trip, missing/new IDs, scoped recall, undo recall, stop/play automation arbitration, and legacy width default. Plugin/routing/console settings excluded from snapshots remain unchanged.
- VM-T6 Automation/concurrency: supported automation moves nodes/faders together; gestures obey current mode. Rapid alternating view edits and out-of-order observer notifications converge on latest engine revision; channel deletion mid-drag does not crash or mutate another ID.
- VM-T7 Performance: 16 active tracks, Vocal Bus/Main slots empty and with declared test providers, Split view open, continuous node drag and automation for 60 seconds. Record cross-view p95 latency <=50 ms, frame/callback/xrun targets from VALIDATION_PLAN.md, queue high-water mark and bounded memory. Separate headless from native evidence.
- VM-T8 Owner workflow: record vocal -> edit/nudge -> create Vocal Bus -> spatially balance lead/doubles/adlibs -> adjust native fader -> observe corresponding node -> adjust width -> compare A/B/C -> save/reopen/export. Inspect 100%,125%,150% scaling, label/handle hit targets, color-independent selected/clipping cues and keyboard numeric entry. Actual owner usability review remains pending until performed.
