P: available portable/cloud host. W: actual Windows build/test runner. H: owner/target interface and plugins. M: physical phone. L: actual listening. Record full SHA, environment, toolchain, settings and exit status for each result; never promote P or cross-build evidence to H/M/L.

## Discovery experiments
X01 (Sprint 1): inspect actual branch, raw prior reports/logs, 38-row ledger, callback ownership and current commands. Prior report names cargo xtask ci; inspect current xtask before running and preserve baseline failures. Output command matrix and evidence index.
X02 (Sprint 1): compare in-process/sandbox timing, declared IPC samples, transport generations, bypass and crash/hang behavior; trace structural mutations and current keypad events. Freeze actual software limits before extending clients.
X03 (Sprint 2, early discovery allowed): identify compatible actual model/STT/TTS runtimes, weights/voice licenses, available CPU/memory and schema-call support. Prefer a no-cost local/self-contained path where feasible. Pin provenance, versions and distribution permissions for code AND each weight/voice. No provider is assumed. Freeze quality, latency/resource bounds and tests before claiming usable runtime. Unknown licenses block use, not justify a fake pass.
X04 (Sprint 3, early discovery allowed): inspect repo CI/build scripts and available Windows toolchain/runner/CPAL/SDK. Distinguish local cross-build, native Windows build and physical interface validation. No runner purchase, SDK redistribution or workflow trigger by unauthorized push. A tested package script can pass while Windows execution remains pending.
X05 (Sprint 4): obtain legitimate official meter vectors or an independent trusted implementation; pin standards/versions/tolerances before comparison. If unavailable, retain analytic results and label independent validation pending. Analyze true peak, gating, channel weights and loudness range separately.
