# Studio workflow, UI and phone remote
Requirements R10–R22 and R37. Reuse the foundation editing, Nudge, toolbar, bus, visual mixer and slot specs.

## Recording and vocal editing
Complete the actual gaps in takes/playlists, comp selection, punch/pre-roll/count-in, markers, fades/crossfades, clip gain/curves, slip/trim/split, grouped/stereo edits, strip-silence preview, consolidation/bounce, undo and exact save/reopen. A destructive command creates a new media asset or deliberate explicit replacement workflow; ordinary edits never rewrite original files. Toolbar tools operate on real shared commands and honor context, locks, selection and Escape.

Arrow, Range, Split, Eraser, Paint, Mute, Bend and Listen must be visible/reachable. Paint includes Freehand, Line, Parabola, Square, Triangle, Saw, Sine and Transform; implement numerical behavior for all, not just menu labels. Linked Arrow/Range and alternate tool require pointer-gesture ownership and focus-loss cleanup. Bend requires a real pitch-preserving render path; establish a legally usable DAW time-stretch baseline in E05, then harden its render integration in Sprint 3. This does not authorize a pitch-correction or note-editing plugin. Do not declare Sprint 2 Bend complete while it only moves markers. No MIDI/instrument creation is introduced by the Paint or quantize tools.

NUDGE remains its own labeled section: amount, unit, target, left/right, previous/next value and actual displacement. Preserve foundation sample accumulation, content-slip sign, trim boundaries, group atomicity, independent Grid and unit rounding. Distinguish numpad and top-row keys. A thousand forward/backward 1 ms steps at 44.1 kHz return exactly to the anchor. Reject invalid grouped edits atomically.

## Both shortcut systems
Build full command inventories for pinned Pro Tools and Studio One editions/versions from primary manuals; the older Nudge bindings remain versioned references. Record every reference command as implemented-and-mapped, intentionally out of recording/mix/master scope, unsupported, or pending native verification, with reason. Do not advertise all shortcuts until all applicable entries work. No-op mapped actions fail coverage.

Provide separate selectable Pro Tools and Studio One profiles, plus Custom and optional user-built hybrid. Profile switch is explicit and reversible. Keep a discoverable default selection; do not mix conflicting mappings automatically. Include transport, recording, edit modes/tools, Nudge, navigation/zoom, selection, fades, gain, automation, mixer, buses, save/export and window actions. Support search, conflict inspector, reassignment, reset, import/export and help showing the active binding. Handle keyboard focus, text entry, plugin windows, numpad, OS-reserved chords and layout differences. Mac bindings can be documented without claiming a Mac build exists. An OS-intercepted shortcut gets a visible alternate, not a global key hook.

## One professional mixer in two views
Console, Visual and Split share selection, values, automation, undo, buses and snapshots. Visual position represents documented gain/pan; width has an explicit control. Include source identification, overlap handling, group selection and precision entry. No separate summing path, native helper plugin requirement or hidden processing. Copy functional workflow goals, not vendor assets or exact trade dress.

Easy bus creation from selected tracks, route inspect, sends/returns, safe deletion, pre/post taps, solo/mute logic, independent send pan, width and bus spill use the foundation contract. Summing/Tape rows have provider, bypass, controls, meter taps, latency and persisted order. Default clean/empty graphs stay clean. Logic-style mode means the documented gain/pan behavior and clean processing profile, not a magic sonic enhancer. Preserve older session graph/profile versions.

Record/Edit/Mix/Master are layouts of one application. Keep transport, track identity, monitoring state, active edit tool and Nudge discoverable. Progressive disclosure can hide advanced controls but cannot hide active processing or latency. Working name SML Studio must not break saved projects, automation IDs or plugin state.

## Speed and skins
Cache menu models and plugin metadata; populate large lists incrementally or virtually. Disk scans, plugin loading and network/model operations cannot run synchronously while opening a menu. First usable menu includes enabled commands and focus, not a blank rectangle. Search is local indexed lookup over installed metadata and commands. Show loading state for a chosen plugin separately from browsing latency.

SML native goals at the fixed validation workload: p95 input-to-usable menu <=50 ms, p95 indexed-search response <=100 ms; record p99/max, cold first opening and warm reopening separately. Target 60 Hz painting where hardware allows; measure delivered frame intervals, not requested timers. Fast menus must retain keyboard navigation, submenu intent and correct enabled state. Never drop commands to improve a percentile.

Themes are validated data: semantic colors, waveform/meter palettes, typography tokens within supported bounds and panel surface tokens. Density, zoom/scaling and workspace placement are separate preferences. Include dark, light and high-contrast starting themes, editor preview, import/export, reset and accessible error fallback. Invalid themes cannot brick launch. No executable scripts, arbitrary network resources or global styles applied to third-party plugin editors. Ensure record/clip/overload states remain identifiable independently of color. Test 100/150/200% scaling and small windows; compare hit testing and rendering.

## SML Remote
Opt-in local service, explicit interface binding, QR pairing with short-lived secret, authenticated revocable sessions and role/action allowlist. Validate Origin as appropriate, reject unauthenticated/stale/replayed commands, rate limit and bound queues; tokens must not appear in shared URLs/logs. Use a practical local HTTPS provisioning route or clearly label a limited browser-only local configuration. A phone's LAN IP HTTP origin is not equivalent to localhost for PWA/security features. Do not claim installability, microphone access or encrypted transport without a real mobile test. No public internet exposure or cloud deployment in this cycle.

Responsive phone controls: play/stop/record, arm/monitor, pre-roll/count-in, markers/loop, take names/rating/audition subject to safe transport rules, track select, basic fader/pan/mute/solo and meters. Native DAW is authoritative for transport and exact timing; network receipt is not sample-accurate execution. Commands return success/rejection and current state; reconnect refreshes a snapshot and never replays old Record. Disconnect leaves native recording running. Meter streams are downsampled/coalesced independently from actions. Two clients cannot silently overwrite stale edits.

Headphone control appears only when a real dedicated cue path exists. Basic monitor volume/dim/mono affect a separate monitor path and never export. If no cue exists, show unavailable; never relabel the Main fader as headphones. Keep direct hardware monitoring distinguishable from software monitoring.

Build knowledge/search over the actual command registry in Sprint 2. Add assistant conversation/actions to desktop and remote in Sprint 4 using the same service. No independent phone-side audio engine or live audio streaming is required. PWA installation and mobile voice remain environment-gated capabilities, reported individually.
