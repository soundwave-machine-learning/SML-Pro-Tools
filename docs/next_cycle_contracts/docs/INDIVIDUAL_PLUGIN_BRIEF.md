# Seven original stock processors
Requirements R23–R31. Working SML names, original interfaces and behavior specifications. Commercial products are references, not source code or a promise of identical sound. Do not restore removed upstream plugins or create custom summing/tape models.

## Common contract before production DSP
For each processor freeze an algorithm dossier in E05: reference edition/version, sources, chosen algorithm and license, signal topology, all parameter IDs/ranges/units/defaults/tapers, stereo/link/MS behavior, sample-rate support, coefficient update/smoothing, denormal/NaN handling, oversampling filters if any, latency/tail reporting, bypass, reset, state history, automation, real-time allocation bounds and objective/listening acceptance. Preserve buildable experiments behind nonshipping flags until accepted. The final quality settings and ranges are not known now; deriving and freezing them is required work, not permission to invent vendor internals.

Every processor needs working UI, numeric input, preset/state migration, A/B, bypass, parameter automation, undo integration, help and accurate metering. Level-matched comparison is an explicit analysis/audition function and does not secretly change export gain. Quality/latency changes use a safe graph rebuild; ordinary bypass keeps compensation. Track dry capture remains unaffected. Independent deterministic offline renders must match repeated renders within the frozen tolerance. Realtime/offline comparison uses identical quality and algorithm settings, with alignment reported.

New native processors are regular inserts or native clip tools. They may expose concise controls in a channel strip, but do not process audio when absent. Do not add a hidden EQ/gate/limiter to every channel to imitate a console.

## Shared analysis and rendering
One source-aware service owns pitch/confidence/voicing, note boundaries, transient/sibilance regions, alignment features and time/pitch maps. Reuse valid analysis between editor and aligner. Realtime Tune may require its own streaming estimator; expose compatible representations without making the offline analysis a callback dependency. A shared interface does not require an unsuitable identical algorithm for both modes.

Pitch detection and modification are separate evaluated components. Define supported range and worst-case latency; test silence, breaths, noise, consonants, creak, vibrato, slides, register boundaries and stereo input. Low confidence must not produce random note jumps. Natural and deliberate hard correction have separate acceptance references. Preserve formants only when enabled and supported, with audible/transient consequences measured.

Align maps must be monotonic with bounded local stretch. User anchors and protected regions win over automatic suggestions. Different wording or missing words must yield local uncertainty or an explicit refusal, not forced alignment of unrelated phrases. Apply pitch matching only to compatible intended unisons unless user explicitly opts in. Timing plus pitch plus manual edits consolidate into one render from original material; editing an already processed cache cannot accumulate degradation.

## Experiment and quality gates
E05 begins in Sprint 1 to identify feasible libraries, native services and licenses; it finalizes each model immediately before that Sprint 3 module. Candidate algorithm selection can proceed autonomously using public research and measured results. A vendor's marketing adjective does not determine transfer curves. Native reference access is useful but not assumed available.

Minimum objective fixtures: filter responses and impulses; dynamics static transfer, attack/release steps, memory/recovery and stereo linking; sidechain routing and phase; anti-alias tests at high drive/quality; latency impulse and bypass transition; finite output/fuzzed parameter sequences; pitch error/cents and voiced/unvoiced classifications on known synthetic signals; time-map landmark error and pitch/formant preservation on a licensed vocal corpus; long automation/state/reset runs. Tolerances for each chosen algorithm must be specified before scoring it. Never tune a threshold after seeing a failing result merely to pass.

Universal hard gates: no non-finite output, no unbounded allocation/queue, correct reported delay within one sample on deterministic delay probes, unchanged original media hashes, valid undo/reopen, no stale render publication, no hidden auto gain and no DSP on empty slots. Musical-quality tests require matched levels, blinded/randomized comparisons where practical, diverse voices and explicit owner/listener observations. Lack of listening access leaves sonic acceptance PENDING; do not invent opinions.

For polyphonic note editing deliver a written feasibility/algorithm/license/CPU/memory/quality study and an isolated prototype only if a defensible route exists. Its outcome must be READY_FOR_EXTENSION or BLOCKED_WITH_REASON and retain the unmet broad parity goal in the handoff. This research output is mandatory even when full polyphonic product work does not fit this cycle.
